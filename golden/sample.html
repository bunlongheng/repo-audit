Full summary
One error convention is now repo-wide: 43/43 routes (incl. the new proxy) run through withErrorHandler, and the jsonl-walker + machines-db extractions from the prior round hold. The layering, multi-machine seam, and documented trust boundaries remain clean. Residuals are two acknowledged lows.
  • Pattern discipline is high: every section is a client component using safeFetch + useMachine().apiBase, every hot route is force-dynamic with a module-level TTL cache; the new SkillUsagePanel.tsx (83 LOC) and skill-usage/route.ts are textbook instances.
  • Multi-machine is a genuine architectural seam: apiBase() (MachineContext.tsx:41) makes remote machines transparent to all 30+ sections, and middleware.ts:8 makes the CORS side correct (Origin echo only for LAN, no Allow-Credentials).
  • Trust boundaries are written down: middleware.ts:61 explains why there is no global auth gate (Host is spoothe model) and points to lib/a2a-auth.ts, where dangerous routes self-guard with timing-safe bearer or strict Sec-Fetch-Site + trusted-Host.
  • Shared error handling is a neighborhood convention, not a repo one: withErrorHandler wraps exactly the 12 app/api/rag/* routes and none of the ~30 app/api/orders/* routes, which hand-roll try/catch.
  • Two coexisting SQLite lifecycles: lib/db/sqlite.ts opens/closes a new Database per call while lib/rag-db.ts holds a process singleton - both work, but a new contributor cannot infer the house style.
  • The jsonl-walker loop (readdir projects -> stat -> mtime filter -> readLastBytes -> per-line JSON.parse) is now copy-pasted across ~9 routes including the new skill-usage/route.ts:61; readLastBytes was already extracted, the walker itself is the next obvious extraction.
  • mcp-server.ts:6 hardcodes RAG_URL = http://localhost:3003, coupling the MCP tool surface to one port despite the registry-driven multi-machine model everywhere else.

Good, Bad, Ugly

Good

  • CI is a real gate: ci.yml runs lint, tsc --noEmit, vitest, and next build on every push; combined with the pre-push typecheck hook, type breakage cannot land.
  • Trust boundaries are engineered, not vibes: timing-safe bearer compare (lib/a2a-auth.ts:6), requireBearerOrSameSite rejects Sec-Fetch-Site:none and untrusted Hosts (CSRF + DNS-rebind), a2a shell exec requires the explicit 'shell.exec ' verb with a comment forbidding a catch-all, and LAN CORS deliberately omits Allow-Credentials with the reasoning inline.
  • SQL hygiene: parameterized queries throughout, dynamic identifiers gated by isSafeIdent (lib/db/sqlite.ts:68) before interpolation.
  • Shared primitives actually got extracted and reused: readLastBytes (lib/safe-read.ts) used by all transcript routes including the new skill-usage/route.ts; withErrorHandler standardizes the rag API neighborhood.
  • Strict TypeScript with zero explicit any across app/ and lib/ (enforced per commit 52f452d), and the codebase comments its own tradeoffs unusually well.
  • The new SkillUsagePanel is a model citizen: 83 LOC, self-hides when empty, machine-aware via apiBase, no new dependencies.

Bad

  • OverviewSection.tsx is an 865-LOC monolith with 9 safeFetch calls and three near-duplicate turn-count->color helpers (getColor :560, cellColor :591, hourColor :693); it keeps absorbing features (SkillUsagePanel mounted at :861) instead of being split.
  • The DbAdapter sqlite->noop fallback silently degrades: when the better-sqlite3 load fails, a2a-db reads return undefined instead of throwing (surfaced by the Node-22 ABI test failures) - in production that same silence presents as an empty dashboard, not an error.
  • Playwright e2e exists but is not in CI, so the section-rendering regressions it would catch ship unverified.
  • lib/db/sqlite.ts opens and closes a new Database on every call while rag-db.ts holds a singleton - one of these is wrong and it is the per-call one.
  • app/api/rag/search/route.ts:12 writes to search_log on every GET (INSERT on the read path) - makes a nominally read-only endpoint a writer and non-idempotent.

Ugly

  • Dead 'true ?' ternary at OverviewSection.tsx:835 - the false branch is unreachable leftover from a week/month toggle; reads as a half-finished refactor shipped to main.
  • package.json:19 freezes lint at 'eslint . --max-warnings 83' - a ratchet that never ratchets; 83 warnings are permanently amnestied and any cleanup below 83 is instantly refillable.
  • A2A accepts 'shell.exec <cmd>' on a LAN-reachable server guarded by ONE static never-rotated bearer in plaintext at ~/.orders/a2a-token; the guard is careful, but a single leaked token = remote shell on every machine in the fleet - no rotation, no per-peer tokens, no audit on use.

Security AuditA

The multi-machine regression is closed with a sound design: a same-origin server proxy (app/api/proxy/route.ts) guarded by requireBearerOrSameSite, private-IP-only peer resolution (isLocalHost, so the shared a2a bearer never reaches a public host), a /api/orders + /api/rag path allowlist re-validated against the WHATWG-normalized URL (defeats %2e%2e and //host smuggling), and forwarding the shared a2a bearer the mesh already uses. MachineContext.apiBase routes remote reads through it; local unchanged. Now covered by 6 security-invariant tests. No open relay, no SSRF to public hosts. Residuals are genuinely low.

Features SupportedA-

Broad but genuinely coherent: every feature is an instance of one thesis - mirror the local orders Code environment (sessions, transcripts, config, memory, usage) and act on it (send input, run skills, sync machines, expose RAG over MCP). Features compose rather than sprawl: the machines registry feeds apiBase which every section uses; RAG feeds the MCP server, Cmd+K search, and the eval harness; the transcript walkers feed tokens, turns, tool-usage, and now the skill/subagent leaderboard. The new Skill & Subagent Usage panel is a well-scoped addition to the analytics branch. Deductions are for edge-of-thesis weight, not incoherence: A2A shell.exec/skill-run is fleet-automation living inside a dashboard, and Overview keeps accreting panels into one 865-LOC component.
